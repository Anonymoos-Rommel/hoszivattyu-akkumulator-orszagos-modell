# V1-068: B04 dynamic-tariff private-output safety

This audit repair changes only manual local file handling in
`tools/materialize_b04_dynamic_tariff.py`. It does not acquire or republish a
source, change tariff formulas, qualify household eligibility, or accept a task.
The fixed source hash, interval count, negative-price reconciliation, CSV fields
and receipt status remain unchanged.

Before any manifest/PDF read, the tool requires both output filenames to be fresh,
untracked and ignored beneath this checkout's `data/interim`. It rejects
symlinked ancestors or targets (including dangling links), nested Git/worktree
markers, tracked-but-deleted targets and failed Git/ignore checks. It checks again
after parsing and creates both output files exclusively, rather than overwriting.
Use a fresh ignored output directory for every materialization.

The dedicated regression tests use disposable Git checkouts, synthetic document
bytes and synthetic parser records. They exercise accepted deep/normalized paths,
public/traversal paths, both target filenames, existing and dangling links, real
nested Git/worktree boundaries, ignore/index errors, rejection before source
reads, late-arriving targets and unchanged CSV/receipt semantics. No real source
panel is regenerated by these tests.

The two-file write is not an atomic transaction: a later receipt creation error
may leave the newly created CSV without a receipt. Existing files are never
removed or rolled back. The checks are not a filesystem sandbox against hostile
concurrent mutation of ancestor directories. The complete numeric panel remains
`EXTERNAL_ONLY`; passing these checks creates no redistribution permission or
national-input closure. No workflow, repository setting, task acceptance,
readiness percentage, policy or model default changes in this repair.
