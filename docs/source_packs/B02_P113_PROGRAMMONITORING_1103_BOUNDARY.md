# B02-P113 — KEHOP PROGRAMMONITORING 1103 AGGREGATION BOUNDARY

## Goal

P112 proved the project-level FAIR monitoring/report export mechanism.

The remaining blocker was whether the complete 4.1.7/4.1.8 cohort can exist as
a source-native cross-project output rather than being reconstructed project by
project.

P113 qualifies the cross-project aggregation layer itself.

## 1. Programmonitoring is explicitly cross-project

The official FAIR/EUPR glossary defines Programmonitoring as the process that
aggregates the results of projects implemented under a programme and then
compares those aggregated results with programme target values.

That establishes:

PROGRAMMONITORING = CROSS-PROJECT RESULT AGGREGATION

This is materially different from the beneficiary-facing project monitoring
export qualified in P112.

## 2. Why this matters for the 1103 route

P109 proves that KEHOP Plusz 4.1.7 and 4.1.8 use the project-level professional
metric:

Energiahatékonysági intézkedés kategória

with the current MEKH category list, where:

1103 = Nyílászáró cseréje

P112 proves that project/report monitoring facts can be source-exported in
FAIR/EUPR.

P113 now proves that FAIR/EUPR also has a native programme-level aggregation
concept over project results.

Therefore a complete source-generated aggregate is not an invented analytical
product class.

## 3. What remains unproven

The FAIR glossary does not state that every project field or every professional
metric is included in programmonitoring aggregation.

P113 therefore does NOT promote:

PROGRAMMONITORING AGGREGATES PROJECT RESULTS

into:

KEHOP 1103 IS CURRENTLY AGGREGATED

No current institutional or public output was identified that directly reports
the 4.1.7/4.1.8 completed-project count carrying exact category 1103.

The exact remaining residual is:

KEHOP_417_418_PROGRAMMONITORING_1103_INCLUSION_OR_INSTITUTIONAL_EXPORT_READBACK_REQUIRED

This can close through either:

1. direct current readback that the exact professional metric is included in
   programmonitoring; or
2. an institutional complete source-generated export/aggregate explicitly
   reporting category 1103 for a declared programme and cutoff scope.

## 4. Minimum admissible aggregate

The minimum admissible output must declare:

- programme scope: 4.1.7 and/or 4.1.8;
- cutoff date;
- exact metric name: Energiahatékonysági intézkedés kategória;
- exact measure code: 1103;
- completed-project denominator;
- completed-project 1103 count;
- complete enumeration for the declared scope;
- source-generated aggregation basis.

This supports only count/frequency.

It does not supply technical window U values and does not classify EKR/HEM
overlap.

## 5. Preferred record route remains

The preferred downstream technical product remains:

FAIR_IH_KEHOP_1103_COMPLETION_RECORD_EXTRACT_REQUIRED

because P108 technical joining still needs stable project identity and final
technical-document keys.
