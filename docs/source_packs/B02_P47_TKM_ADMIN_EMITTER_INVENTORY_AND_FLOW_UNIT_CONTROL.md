## 1. Purpose

P46 identified a current Hungary-specific commercial national radiator-stock package but did not obtain its numeric cells.

P47 follows the user's programme intent rather than stopping at provider discovery:

`HOW MANY + WHAT TYPE + KEEP/CHANGE + HOW MANY NEW UNITS -> B06`

The immediate question is whether a large current Hungarian administrative process already records radiator/emitter quantities at a useful grain, without sending a bespoke data request.

The answer is **yes for TKM/2025 participating district-heated projects on the cost-allocator route**.

P47 also closes a dangerous market-flow interpretation path. A commercial radiator-market page can display a generic quantity label such as `units`, while the underlying HS trade authority records quantities in **kilograms**. Such values cannot be treated as physical radiator piece counts.

Core boundaries:

`ADMIN RECORD SCHEMA != PUBLIC AGGREGATE != NATIONAL P42 STOCK AUTHORITY`

`COST-ALLOCATOR ROUTE -> PER-EMITTER RECORD SURFACE`

`APARTMENT HEAT-METER ROUTE != PER-RADIATOR RECORD SURFACE`

`PROJECT COVERAGE != NATIONAL STOCK COMPLETENESS`

`MARKET FLOW KG != INSTALLED STOCK UNIT COUNT`

`GENERIC "UNITS" LABEL != PHYSICAL RADIATOR PIECES`

No external source binary is committed to the public repository.

## 2. Official TKM/2025 implementation authority

Primary source:

- programme: `TKM/2025 — Távolról leolvasható fűtési költségmegosztók felszerelése távhővel ellátott lakóépületeknél`;
- issuer/implementation authority: Nemzeti Energetikai Ügynökség Zrt. / FEAK Zrt.;
- document: `Általános Pályázati és Projekt Megvalósítási Útmutató`;
- official URL: `https://www.nffku.hu/images/tavolrol/02_Altalanos_Palyazati_%20Projekt_Megvalositasi_Utmutato.pdf`.

The guide states that the electronic application system is the mandatory submission route and the closing professional/financial report is submitted electronically after physical completion.

### 2.1 Exact equipment type and quantity fields

Exact locator: guide, PDF page 19, invoice-detail requirements.

The invoice must identify, as applicable:

- installed registered remotely readable heating cost allocator **type and count**;
- configured walk-by cost allocator **count**;
- data-collector **type and count**;
- thermostatic radiator valve head/body and lower return radiator valve **type and count**.

This is stronger than a generic statement that a project contains radiators. It proves an administratively required exact equipment-quantity surface.

### 2.2 Heat-emitter quantity is an auditable project field

Exact locator: guide, PDF page 29, extraordinary inspection items.

The authority may check the correctness of project information including the **quantity of heat emitters recorded in the application / contractor agreement**.

Therefore:

`HEAT-EMITTER COUNT = AUDITABLE PROJECT FIELD`

not merely an optional installer note.

## 3. Official technical handover proves dwelling-level realised counts

Second primary source:

- document: TKM/2025 `Műszaki átadás-átvételi jegyzőkönyv`;
- official URL: `https://nffku.hu/images/tavolrol/15_Muszaki_atadas_atveteli_jegyzokonyv.pdf`;
- exact locator: PDF page `2 / 4`.

The template is generated by the electronic application system from its recorded data. Its table binds rows to:

- building / staircase;
- floor and door;
- land-registry identifier;
- dwelling / non-dwelling separately owned unit.

For the relevant technical activities it carries both:

- `VSZ szerint (db)` — contracted count;
- `Megvalósult (db)` — realised count;
- reason for deviation.

The activity columns include:

1. new or replacement remotely readable heating cost allocators;
2. walk-by configuration;
3. thermostatic radiator valve head/body and lower return radiator valve installation/replacement;
4. data collector works.

This proves a current implemented administrative lineage:

`PROJECT -> DWELLING -> CONTRACTED DEVICE COUNT -> REALISED DEVICE COUNT`

For cost-allocator installations the device is mounted on a heat emitter, so this is a usable emitter-count surface for the participating project population.

## 4. Legal semantics: why cost allocators map to emitters but apartment heat meters do not

Primary legal source:

- `157/2005. (VIII. 15.) Korm. rendelet`;
- Nemzeti Jogszabálytár;
- URL: `https://njt.hu/jogszabaly/2005-157-20-22.34`.

The regulation defines `hőleadó készülék` to include:

- fűtőtest;
- radiátor;
- csőregiszter;
- other heating device operated with the heat-carrier medium.

For the cost-allocation route the regulation requires the heat output of **all heat-emitting devices** in the relevant separately owned/used parts to be determined with same-system heating cost allocators, **or** the heating consumption can be independently measured by a heat meter serving the cost-allocation function.

Therefore the admissible interpretation is:

`COST ALLOCATOR COUNT ~= COVERED HEAT-EMITTER COUNT WITHIN THAT PROJECT ROUTE`

but:

`INDEPENDENT APARTMENT HEAT METER != RADIATOR COUNT`

P47 does not silently mix these two legal alternatives.

## 5. What TKM/2025 does and does not solve

For participating TKM/2025 projects using the per-emitter cost-allocator path, public official documents prove that the underlying administrative process carries:

- heat-emitter quantity as an auditable field;
- cost-allocator device type and count;

Hard boundary:

`RECORD EXISTS IN ADMIN SYSTEM != RECORD IS PUBLICLY AGGREGATED`

`TKM PROJECT POPULATION != ALL HUNGARIAN HYDRONIC DWELLINGS`

## 6. Market-flow unit correction

P46 retained IndexBox only as a market-flow diagnostic. P47 adds an explicit unit guard because generic commercial labels can be mistaken for physical pieces.

Independent quantity-unit authority:

- World Integrated Trade Solution / UN Comtrade;
- Hungary, 2022, HS `732219` — `Radiators and parts thereof, iron or steel, other`;
- URL: `https://wits.worldbank.org/trade/comtrade/en/country/HUN/year/2022/tradeflow/Exports/partner/ALL/product/732219`.

WITS reports Hungary's 2022 exports as:

- quantity: `18,512,700`;
- quantity unit: **`Kg`**;
- trade value: `49,192.02` thousand USD.

The corresponding WITS world-import surface records Hungary's 2022 HS 732219 imports as `16,456,500 Kg`.

Therefore market-flow quantities in this product family have an authoritative mass basis in the underlying trade data.

P47 freezes:

`HS 732219 TRADE QUANTITY UNIT = KG`

`KG != PIECE`

`RADIATORS AND PARTS HS CATEGORY != COMPLETE PHYSICAL RADIATOR COUNT`

A commercial market page using the word `units` is not sufficient evidence that the number is a count of complete radiators.

## 7. Executable controls

`modules/B02/admin_emitter_inventory_control.py` exposes two separate gates.

### 7.1 Administrative inventory gate

`assess_admin_emitter_inventory()` qualifies a surface only when current Hungarian official evidence proves:

- exact authority and locator;
- dwelling-level binding;
- per-emitter cost-allocator route rather than apartment-level heat-meter substitution;
- emitter count field;
- installed device type field;
- realised count field;
- auditable heat-emitter quantity;
- reproducible binding.

A qualified administrative inventory surface does not self-authorize P42.

### 7.2 Market-flow unit gate

`assess_market_flow_unit()` requires a physical piece mapping before any generic market `unit(s)` label can become a radiator piece count.

If the authoritative quantity unit is `KG`, physical-piece authority is false.
